# Railway 3X-UI Sanaei — Ubuntu 24.04

این پروژه از خود 3X-UI رسمی MHSanaei استفاده می‌کند؛ رابط کاربری، backend، Xray management، database و link/subscription generation از 3X-UI رسمی می‌آیند و UI بازنویسی نشده است.

نسخه هدف: v3.5.0

Railway adaptation:
- Ubuntu 24.04 base
- official 3x-ui release binary downloaded during image build
- nginx edge router
- Railway `$PORT` is the only public HTTP/HTTPS listener
- Railway TLS terminates at the public domain on 443
- Xray inbounds are internal
- no Railway TCP Proxy is required for WS/XHTTP/gRPC/HTTP Upgrade over Railway HTTPS

IMPORTANT:
This is not a fork/reimplementation of the 3X-UI interface. It runs the official 3X-UI binary and adds only the Railway process/edge layer.

Recommended Railway environment variables:
RAILWAY_PUBLIC_DOMAIN = your generated Railway domain (optional; Railway normally provides it automatically)
XUI_PORT = 2053
XUI_INIT_WEB_BASE_PATH = /panel/

For the first deployment, use one public HTTP/HTTPS domain generated by Railway.

Default internal Xray transport ports reserved by the edge configuration:
8081 = WS
8082 = XHTTP
8083 = gRPC
8084 = HTTP Upgrade

Create the corresponding inbounds in 3X-UI on those internal ports.

External client links should use:
https://<RAILWAY_PUBLIC_DOMAIN>:443

Do NOT enable TLS inside those Xray inbounds when Railway is terminating HTTPS. In 3X-UI, use security=none for the internal Xray inbound and set the public Host/SNI/address to the Railway domain in the inbound Host/External Proxy/link settings as appropriate.

The Railway edge terminates TLS; therefore the client still uses WS TLS / XHTTP TLS / gRPC TLS / HTTP Upgrade TLS at the public endpoint.

Panel:
https://<RAILWAY_PUBLIC_DOMAIN>/panel/

Persistence:
Mount a Railway Volume at /data. The startup script stores the 3X-UI database and certificates/configuration under /data/x-ui.

## TCP Proxy / REALITY

For Xray RAW/TCP + REALITY, Railway Public HTTPS cannot be used because REALITY is a raw TLS-like TCP protocol and requires end-to-end TCP.

This package reserves internal TCP port `8443` for the REALITY inbound.

Railway Dashboard:
1. Open the deployed Service.
2. Go to Networking.
3. Add a **TCP Proxy**.
4. Set the target/service port to `8443`.
5. Railway will assign an external TCP proxy port. Do not assume it is 443.
6. Use the generated `xxxxx.proxy.rlwy.net:<TCP_PROXY_PORT>` endpoint in the REALITY client configuration.

3X-UI:
- Create a VLESS inbound.
- Port: `8443`
- Network: `TCP` / RAW
- Security: `REALITY`
- Flow: `xtls-rprx-vision` when using VLESS Vision
- Generate REALITY key pair and short IDs in 3X-UI.
- Select a suitable REALITY dest/serverNames according to your configuration.

The public HTTPS domain remains dedicated to:
443 -> Railway HTTPS -> Nginx -> WS/XHTTP/gRPC/HTTPUpgrade

The Railway TCP Proxy is dedicated to:
TCP_PROXY_EXTERNAL_PORT -> service:8443 -> Xray REALITY

These are intentionally separate listeners.

## Fixed build dependency
`envsubst` is provided by Ubuntu package `gettext-base`; the Dockerfile now installs it explicitly.

## v2 startup fix
All XUI environment variables have safe defaults under `set -u`; `XUI_BIN_FOLDER` defaults to `/usr/local/x-ui/bin`, and the log file is created before startup.

## v3 startup fix
Removed the fragile `XUI_BIN_FOLDER` environment assignment from the startup command. With `set -u`, an unset variable could terminate the container before 3X-UI starts.
